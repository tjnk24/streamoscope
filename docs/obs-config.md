# How OBS stores the settings the installer changes

Notes for `configure-obs.ps1`. Checked against the OBS Studio source (tags 28.0.0, 30.0.0, 31.0.0, 32.0.0),
obs-websocket (5.4.2 to 5.7.6) and a real OBS 33 config. All changes are made only while OBS is closed:
OBS keeps these settings in memory and writes them back on exit.

## Config folder

- Normal install: `%APPDATA%\obs-studio`.
- Portable install: `<OBS folder>\config\obs-studio`. OBS is portable when it is started with `--portable` / `-p`
  or when one of `portable_mode`, `obs_portable_mode`, `portable_mode.txt`, `obs_portable_mode.txt`
  lies in the OBS folder (two levels above `bin\64bit\obs64.exe`).
- `global.ini` always lies in this folder. From OBS 31 its section `[Locations]` (`Configuration`, `SceneCollections`,
  `Profiles`, `PluginManagerSettings`) holds the base folders for the rest, with doubled backslashes; by default
  they all point to `%APPDATA%`, and `obs-studio\user.ini`, `obs-studio\basic\scenes` and `obs-studio\basic\profiles`
  are under them.
  The script reads these paths and falls back to the config folder when the section or a key is missing (OBS 28–30).

## When there is nothing to configure

There is no `global.ini` and no `user.ini` when OBS (or a portable copy) was installed but never started,
when its settings were deleted, or when OBS is not installed. The script then changes nothing:
the installer asks to start OBS once (or to choose the OBS folder for a portable copy) and run setup again.

## Custom browser docks

- Key `ExtraBrowserDocks` in section `[BasicWindow]`. The value is a JSON array on one line:
  `[{"title": "...", "url": "...", "uuid": "..."}]`.
- File: `global.ini` in OBS 28–30, `user.ini` from OBS 31.
- `uuid` is optional; OBS stores it as 32 hex characters without dashes or braces.
- The dock's Qt object name is `<title>_extraBrowser`, so titles must be unique.
- A dock added while OBS is closed is not listed in the saved `DockState`. OBS sets no visibility for it on load,
  but it is still shown on the next start: checked on OBS 33.0.1, where the dock added by the installer appeared
  right away. DockState is never edited.
- With no saved `DockState` at all (OBS has never been closed with these settings) OBS resets the layout and leaves
  extra docks floating and hidden. The page still loads once, but the next start doesn't create the dock.
  Seen on OBS 33.0.1. Asking to start OBS once before setup avoids this, and the test stand does the same.
- Both files are UTF-8 with BOM and LF line endings.

### Which file to edit

OBS 31 migrates once: if `[General] LastVersion` in `global.ini` is below 31.0.0 and `Pre31Migrated` is not set,
it copies `global.ini` to `user.ini`. If `user.ini` already exists at that moment, OBS shows an error
and the migration is skipped. So:

- `user.ini` exists → edit `user.ini`.
- Only `global.ini` exists → edit `global.ini`, never create `user.ini`. OBS 31+ copies it on the next start.
- Neither exists (OBS was never started) → change nothing and ask to start OBS once.

## Bridge script

- Every scene collection is `basic\scenes\<name>.json` (UTF-8 without BOM, names may be Cyrillic).
  Files ending with `.json.bak` or `.json.v1` are OBS backups and are skipped.
- Scripts are listed in `modules["scripts-tool"]`: an array of `{"path": "...", "settings": {}}`.
  The path is stored as OBS got it from the file dialog, usually with forward slashes; compare paths
  case-insensitively and with both separators.
- Scripts are per scene collection, so the bridge is added to every collection.

## Profile parameters

- Every profile is `basic\profiles\<folder>\basic.ini` under the `Profiles` base folder (UTF-8 with BOM, LF).
- Profile parameters that obs-websocket (`SetProfileParameter`) and scripts write are sections and keys of that file.
  The bridge and the dock use `[StreamoScope]` (`PluginOutputs`, the command keys); before 0.3.0 it was `[ObsStatsDock]`.
  OBS keeps sections it doesn't know as they are.
- Uninstall removes both sections from every profile, with the lines in them and the blank line after them.

## obs-websocket

- obs-websocket 5.5.0 and later: `plugin_config\obs-websocket\config.json` with `server_enabled`, `server_port`,
  `auth_required`, `server_password`, `first_load`, `alerts_enabled`.
- Earlier 5.x (OBS 28–30): section `[OBSWebSocket]` in `global.ini` with `ServerEnabled`, `ServerPort`,
  `AuthRequired`, `ServerPassword`, `FirstLoad`, `AlertsEnabled`. Newer versions move these keys into
  `config.json` on start and remove them; while they exist, they take priority over `config.json`.
- On the very first start obs-websocket generates a random password, keeps authentication on
  and leaves the server off.
- The installer only turns the server on (`server_enabled` / `ServerEnabled`) in the file that is in use.
  If there is no obs-websocket config yet, it creates nothing: the password is generated by OBS
  and the dock explains how to turn the server on. The password is never read, logged or changed.
