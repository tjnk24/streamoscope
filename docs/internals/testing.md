# Как проверять

| Что менял | Чем проверять |
| --- | --- |
| Логику панели | `npm run test:unit`, входит в `npm test` |
| Панель глазами | `npm run start:dev` или `preview_start` с именем `dock-dev` |
| Журнал без OBS | `npm run start:dev` с включёнными моками, файл `.dev-journal/streamoscope.log` |
| Код моста на Lua, загрузчик, заглушка, откат | `npm run test:bridge`: настоящий LuaJIT из OBS, путь с кириллицей, без самого OBS; судейство пробы загрузчиком 0.6.0 (`harness/loader_0_6_0.lua`) |
| Настройку OBS и обновлятор | `npm run test:installer` |
| Панель в настоящем OBS, поток, обновление и откат | тестовый стенд, `npm run test:stand` |

## Тестовый стенд

- **Портативный OBS той же версии, что у пользователя, и локальный RTMP-сервер** в `.test-stand` (в git не попадает). Настройки пользователя, его OBS, сцены и ключи стенд не трогает, поэтому **Claude запускает его сам**: это и есть проверка в настоящем OBS.
- **Перед запуском** убеждаемся, что пользователь не стримит и не играет (нет настоящего `obs64` и тяжёлых процессов): стенд открывает окно OBS. Вопрос брандмауэра Windows можно отклонить - всё идёт через `127.0.0.1`.
- **`npm run test:stand`** прогоняет всё, останавливает стенд и пишет `ALL PASSED`; около 5 минут и 900 МБ на диске:
  1. Запускает и закрывает OBS, как просит установщик, ставит текущий код настоящим `configure-obs.ps1` в папку с кириллицей.
  2. Запускает OBS: вход в панель с паролем, отчёт о здоровье, поток до RTMP-сервера, битрейт в панели.
  3. Журнал: строки моста и панели, статистика, нет пароля, адресов и путей, выключение и включение.
  4. «Обновить» до `9.0.0`: скачивание, подпись, перезапуск, новая версия, конец пробы.
  5. `9.0.1` со сломанной панелью: откат после перезапуска, текст в карточке.
  6. Фоновое обновление до `9.0.2` примерно через минуту после запуска.
  7. `9.0.3` с исправными мостом и панелью, но сломанным загрузчиком версии (вызывает `nil`: `error()` в OBS не бросает, `bridge.md`): фоновое обновление, перезапуск - пробу судит загрузчик `9.0.2` (`healthy-loader.txt`), панель `9.0.3` отчитывается, проба кончается; ещё перезапуск - заглушка запускает сломанный загрузчик и откатывается на `9.0.2` с отметкой в `rolled-back-version.txt`, следующий запуск открывает `9.0.2` и карточку с текстом об откате.
- **Отдельные команды - `npm run stand -- <команда>`** (без аргументов - список): `setup`, `install`, `release <версия> [--broken|--broken-loader]` (падающая панель или падающий загрузчик версии), `start`, `stop`, `status`, `stream on|off`, `update <версия>`, `open-settings`, `evaluate <выражение>`, `screenshot <файл.png>`.
  - `evaluate` и `screenshot` работают через отладочный порт Chromium, мышь и экран не нужны.
  - После `stand -- install` и `start` панель уже подключена; `status` показывает версии, файлы обновления, текст панели и состояние потока.
- **Тестовые сборки - вне проекта**, в соседней `streamoscope-test-builds`: временная копия проекта `project-copy` (удаляется после сборки, в ней версия тестового выпуска) и свой кэш webpack `webpack-cache` (`WEBPACK_CACHE_DIRECTORY`). С `start:dev` и `build:prod` в проекте не пересекаются, папку можно удалить в любой момент, кроме работы стенда.
- **Не проверяет**: снятую галку дока в меню Docks (нужно нажимать в окне OBS; вручную на стенде: страница панели не создаётся, `panel=0`, отката нет), настоящий GitHub и настоящий установщик - выпуски только с тестового сервера.
- **Версии OBS и RTMP-сервера с SHA-256** - `scripts/testStand/consts.ts`; у пользователя вышел новый OBS - обновляем там.
- **В настоящем OBS пользователя** изменение моста подхватывается так: Инструменты → Скрипты → «Перезагрузить скрипты», затем «Скопировать диагностику» в панели.

## Разработка в браузере

- **`npm run start:dev`** (`http://localhost:3062`): панель ходит в настоящий OBS и подключается сама, без пароля; не запущенный OBS подхватит, как только он поднимется.
- Компоненты обновляет React Fast Refresh. Одиночки (`obsConnectionService`, `store`, `routerManager`) отказываются от горячей замены (`import.meta.webpackHot?.decline()`): правка в них или в их импортах перезагружает страницу.
- Eslint под dev-сервером не запускается: его ошибка ломает сборку, и обновления перестают применяться. Файлы - в памяти, `build` не трогается.

## Обновление целиком тестовой сборкой

Обычно хватает `npm run test:stand`. Тестовая сборка установщика нужна, когда проверяем сам `setup.exe`; ставит её пользователь из Проводника.

- **Переменные `TEST_UPDATE_SERVER` (`http://127.0.0.1:3063`) и `TEST_UPDATE_PUBLIC_KEY` при `npm run package:installer`.**
  - Webpack подставляет `process.env.TEST_UPDATE_SERVER`, и транспорт GitHub берёт его базовым адресом вместо `https://api.github.com/repos/tjnk24/streamoscope/` (`GITHUB_BASE_URL` в `src/api/github/transport/consts.ts`); пути те же: `<сервер>/releases/latest`, `<сервер>/releases`.
  - `scripts/buildInstaller/stageTestUpdater` заменяет в `updater/Update-Widget.ps1` папки выпуска значения по умолчанию `ReleaseBaseUrl`, `LatestReleaseUrl` и `PublicKey`.
  - Без переменных сборка обычная. Подмены «на лету» в обновлятор не встраиваем, чтобы настоящую установку нельзя было перенаправить.
- **Поддельный выпуск - `npm run serve:test-release -- <папка>`** (`scripts/serveTestRelease`): `/releases/latest` (его же берёт тестовый обновлятор) и `/releases` из одного выпуска в формате GitHub API со строкой совместимости и старой датой публикации (иначе фоновая проверка ждала бы 48 ч), файлы - по `/download/v<версия>/...`, CORS открыт для `file://`; `--broken-signature` отдаёт чужую подпись архива.
  - В папку кладём подписанные `streamoscope-<версия>.zip` (верхний уровень - папка `streamoscope-<версия>`) и `compatibility.json`.
  - Тестовый ключ (`minisign -G -W`) и более новая версия (копия проекта с поднятой `version` и ссылкой на `node_modules`) - в `.test-stand`, их делает `npm run stand -- release <версия>`: `package:release` в начале удаляет всю `release/`.
  - После проверки ставим обычную сборку.
- **Обновлятор без OBS** - на черновой раскладке установки с подменённым `LOCALAPPDATA`; настоящую установку это не трогает, кроме `DisplayVersion` в реестре, поэтому в копии `consts.ps1` подменяем `UninstallRegistryKey`.
- **Тихий установщик при существующей установке ставит в её папку и игнорирует `/DIR`** (Inno берёт прежнюю папку по `AppId`). Поэтому проверки в черновой папке с подменённым `APPDATA` - только без настоящей установки, иначе обновятся её файлы (настройки OBS не тронуты: скрипт смотрит в черновой `APPDATA`).
- **Проверка без OBS пользователя**: тихая установка в черновую папку (`/DIR=`) с `APPDATA` и `LOCALAPPDATA` на копию настроек OBS, где пути `[Locations]` в `global.ini` переписаны на копию; до и после сверяются хэши настоящих файлов OBS.
