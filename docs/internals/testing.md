# Как проверять

| Что менял | Чем проверять |
| --- | --- |
| Логику панели | `npm run test:unit`, входит в `npm test` |
| Панель глазами | `npm run start:dev` или `preview_start` с именем `dock-dev` |
| Журнал без OBS | `npm run start:dev` с включёнными моками, файл `.dev-journal/streamoscope.log` |
| Код моста на Lua, загрузчик, заглушка, откат | `npm run test:bridge`: настоящий LuaJIT из OBS, путь с кириллицей, без самого OBS; судейство пробы загрузчиком 0.6.0 (`harness/loader_0_6_0.lua`) |
| Настройку OBS и обновлятор | `npm run test:installer` |
| Панель в настоящем OBS, поток, обновление и откат | тестовый стенд, `npm run test:stand` |

## Тестовый стенд

Портативный OBS той же версии, что у пользователя, и локальный RTMP-сервер в папке `.test-stand` (в git не попадает). Настройки пользователя, его OBS, сцены и ключи стенд не трогает, поэтому **Claude запускает его сам, без просьбы к пользователю**: это и есть способ проверить изменение в настоящем OBS. Запускается окно OBS, поэтому перед запуском убеждаемся, что пользователь не стримит и не играет (нет настоящего `obs64` и тяжёлых процессов). Если Windows спросит про брандмауэр, можно отказать: всё работает через `127.0.0.1`.

`npm run test:stand` прогоняет всё сразу, в конце останавливает стенд и пишет `ALL PASSED`. Занимает около 3 минут и около 900 МБ на диске:

1. Один раз запускает и закрывает OBS, как просит установщик, затем ставит текущий код настоящим `configure-obs.ps1` в папку с кириллицей.
2. Запускает OBS, проверяет вход в панель с паролем, отчёт о здоровье, поток до RTMP-сервера и битрейт в панели.
3. Журнал: строки моста и панели, статистика, нет пароля, адресов и путей, выключение и включение.
4. Кнопка «Обновить» до `9.0.0`: скачивание, подпись, перезапуск, новая версия, конец пробы.
5. Выпуск `9.0.1` со сломанной панелью: откат после перезапуска, текст в карточке.
6. Фоновое обновление до `9.0.2` примерно через минуту после запуска.

Отдельные команды - `npm run stand -- <команда>`, без аргументов выводит список: `setup`, `install`, `release <версия> [--broken]`, `start`, `stop`, `status`, `stream on|off`, `update <версия>`, `open-settings`, `evaluate <выражение>`, `screenshot <файл.png>`. `evaluate` и `screenshot` работают с панелью через отладочный порт Chromium, поэтому мышь и экран не нужны. После `stand -- install` и `start` панель уже подключена, `status` показывает версии, файлы обновления, текст панели и состояние потока.

Тестовые сборки стенд делает вне проекта, в соседней папке `streamoscope-test-builds`: там временная копия проекта (`project-copy`, удаляется сразу после сборки, в ней версия тестового выпуска) и свой кэш webpack (`webpack-cache`, задаётся переменной `WEBPACK_CACHE_DIRECTORY`). С `npm run start:dev` и `npm run build:prod` в самом проекте они не пересекаются, и папку можно удалить в любой момент, кроме работы стенда.

Снятую галку дока в меню Docks сценарий не проверяет: для этого нужно нажимать в окне OBS. Такой запуск проверен вручную на стенде: со снятой галкой страница панели не создаётся, в пробном файле `panel=0`, отката нет.

Стенд проверяет выпуски только с тестового сервера. Запрос к настоящему GitHub и установку настоящего установщика он не заменяет. Версии OBS и RTMP-сервера с их SHA-256 - в `scripts/testStand/consts.ts`; у пользователя вышел новый OBS - обновляем там.

В настоящем OBS у пользователя изменение моста подхватывается так: Инструменты → Скрипты → «Перезагрузить скрипты», затем «Скопировать диагностику» в панели.

## Разработка в браузере

- **Разработка в браузере - `npm run start:dev`** (`http://localhost:3062`, панель ходит в настоящий OBS и подключается сама, без ввода пароля; если OBS ещё не запущен, подхватит его, как только он поднимется). Компоненты обновляются через React Fast Refresh без перезагрузки; модули-одиночки (`obsConnectionService`, `store`, `routerManager`) отказываются от горячей замены (`import.meta.webpackHot?.decline()`), и правка в них или в том, что они импортируют, перезагружает страницу. Eslint под dev-сервером не запускается: ошибка eslint ломает сборку, и dev-сервер перестаёт применять обновления. Dev-сервер держит файлы в памяти и `build` не трогает.

## Проверка обновления целиком тестовой сборкой

Обычно хватает `npm run test:stand`. Тестовая сборка установщика нужна, когда проверяем сам `setup.exe`, и ставит её пользователь из Проводника.

- **Проверка обновления целиком - тестовой сборкой.** Переменные `TEST_UPDATE_SERVER` (`http://127.0.0.1:3063`) и `TEST_UPDATE_PUBLIC_KEY` при `npm run package:installer`: webpack подставляет `process.env.TEST_UPDATE_SERVER`, и транспорт GitHub панели берёт его вместо `https://api.github.com/repos/tjnk24/streamoscope/` базовым адресом (`GITHUB_BASE_URL` в `src/api/github/transport/consts.ts`), поэтому пути те же, что у GitHub: последний выпуск - `<сервер>/releases/latest`, список для «Что нового» - `<сервер>/releases`, а `scripts/buildInstaller/stageTestUpdater` заменяет в `updater/Update-Widget.ps1` папки выпуска значения по умолчанию `ReleaseBaseUrl`, `LatestReleaseUrl` и `PublicKey`. Без переменных сборка обычная; подмены «на лету» в обновлятор не встраиваем, чтобы настоящую установку нельзя было перенаправить. Поддельный выпуск раздаёт `npm run serve:test-release -- <папка>` (`scripts/serveTestRelease`): `/releases/latest` (его же берёт тестовый обновлятор) и `/releases` из одного этого выпуска в формате GitHub API со строкой совместимости и старой датой публикации (иначе фоновая проверка ждала бы 48 ч) и файлы по `/download/v<версия>/...`, CORS открыт для страницы `file://`; `--broken-signature` отдаёт чужую подпись архива. В папку кладём подписанные `streamoscope-<версия>.zip` (верхний уровень архива - папка `streamoscope-<версия>`) и `compatibility.json`. Тестовый ключ (`minisign -G -W`) и более новую версию (копия проекта с поднятой `version` и ссылкой на `node_modules`) держим в `.test-stand`, их делает `npm run stand -- release <версия>`: `package:release` в начале удаляет всю `release/`. После проверки ставим обычную сборку. Обновлятор можно прогнать и без OBS на черновой раскладке установки с подменённым `LOCALAPPDATA`; настоящую установку это не трогает, кроме `DisplayVersion` в реестре: в копии `consts.ps1` подменяем `UninstallRegistryKey`.
- **Если на машине уже есть установка, тихий установщик ставит в её папку и игнорирует `/DIR`** (Inno берёт прежнюю папку по `AppId`). Проверки в черновой папке с подменённым `APPDATA` делаем только когда настоящей установки нет; иначе они обновят её файлы (настройки OBS при этом не тронуты: скрипт смотрит в черновой `APPDATA`).
- **Проверка без вашего OBS**: тихая установка в черновую папку (`/DIR=`) с подменёнными `APPDATA` и `LOCALAPPDATA` на копию настроек OBS, где пути `[Locations]` в `global.ini` переписаны на копию; до и после сверяются хэши настоящих файлов OBS.
