# Правила работы в этом репозитории

OBS Custom Browser Dock: React 19, antd 6, Redux Toolkit, react-router 8, CSS-модули, webpack + swc.
Панель открывается с диска (`file:///.../build/index.html`), ходит в obs-websocket на `127.0.0.1` и, при проверке обновлений, в API GitHub за последним выпуском.

## Где что лежит

Правила по областям Claude Code подгружает сам из `.claude/rules/`, когда открыт подходящий файл: TypeScript, панель, Lua, PowerShell, установщик, тесты, сборка, выпуски. Если правка началась без чтения файлов этой области (например, команда `npm install` или выпуск), сначала прочитай нужный файл оттуда.

Как устроены части программы - `docs/internals/`, читаем перед правкой этой части:

- `bridge.md` - загрузчик моста, автооткат, команды через параметр профиля.
- `updater.md` - `Update-Widget.ps1`: фоновая проверка, порядок установки, статус и ошибки.
- `installer.md` - настройка OBS, раскладка установки, Inno Setup, `minisign.exe`.
- `dock.md` - обновления в панели, плашка моста и переключение коллекций, карточка обновлений, диагностика, ошибки, вход, моки.
- `testing.md` - какими командами что проверять, тестовый стенд.

Форматы настроек OBS - `docs/obs-config.md`, выпуск и обновления для людей - `docs/DEVELOPMENT.md`.

## Общие правила кода

- **Имена - человекочитаемые, везде**: переменные, параметры, счётчики циклов, константы, функции, в TS и в Lua. Никаких `i`, `n`, `d`, `x`, `K`, `H0`, `t1`, `ror`, `cb`, `el` - имя говорит, что лежит внутри (`wordIndex`, `candidate`, `divisor`, `roundConstants`, `rotateRight`). Даже если так названо в стандарте или алгоритме - даём смысловое имя. Поля чужих протоколов (`op`, `d` в obs-websocket) при деструктуризации переименовываем: `{op: opCode, d: data}`. Неиспользуемый параметр - `_` плюс имя (`_output`, `_index`).
- **Сначала прецедент, потом код.** Новый роут, селектор, слайс, сервис пишутся так же, как соседние.
- **Выносим только то, что повторяется.** Разовый текст - в разметке, а не в `consts.ts`; хелпер с одним вызовом - в месте вызова.
- **Больше 7 файлов одного вида в папке - раскладываем по подпапкам по смыслу** (типы, утилиты, компоненты, модули Lua, функции PowerShell): по области, как `src/types/obs` или `utils/<назначение>/`, а не по алфавиту или виду файла. Подпапки - не глубже трёх уровней от исходной папки, в каждой - тоже не больше 7 файлов, иначе делим её дальше. Подпапка из одного файла не нужна: такой файл остаётся уровнем выше. Исключение - папки данных страницы `api/`, `services/`, `loaders/`, `selectors/` и `reducers/` и эндпоинты API в `src/routes/api/`: они есть всегда, даже с одним файлом, чтобы искать их в одном месте. Добавляя файл в папку, где уже 7, сначала раскладываем папку. Не считаются корень репозитория (конфиги инструментов должны лежать там) и служебные папки инструментов (`.husky/_`, `node_modules`, `build`, `release`).
- **Комментариев в коде нет совсем** - ни в TS, ни в SCSS, ни в Lua, ни в конфигах. Остаются только директивы инструментов (`/* eslint-disable ... */`, `/// <reference ... />`). Пустой `catch` без комментария - `catch { return; }`.

## Безопасность

- **Ключ трансляции не читаем и не показываем.** Из `GetStreamServiceSettings` берутся только `service` и `server`; скрипт-мост отдаёт только схему и хост сервера.
- **Пароль obs-websocket вводит пользователь**, хранится только в localStorage панели и сохраняется всегда после успешного входа (OBS сам держит его открытым текстом в своём конфиге). Сохранённый пароль в поля не подставляем.
- **Исключение - `npm run start:dev`**: dev-сервер отдаёт порт и пароль из конфига obs-websocket (`plugin_config/obs-websocket/config.json` в папке настроек OBS) по `/dev/obs-connection`, читая файл при каждом запросе, и слушает только `localhost`. Панель забирает их при старте, если собрана dev-сервером (`process.env.IS_DEV_SERVER`); в production-сборку этот код и пароль не попадают.
- **Личных путей и данных в репозитории нет** - он публичный.

## Процесс

- **Перед правкой описать, что собираешься менять.**
- **README.md и docs/DEVELOPMENT.md - только на английском и всегда актуальные.** README - для пользователя (возможности, установка, ограничения, проверка скачанного), `docs/DEVELOPMENT.md` - для разработчика (команды `npm`, выпуски, проверка обновлений, установщик). Изменение, которое видит пользователь или разработчик (новая функция, настройка, площадка, шаг установки, скрипт `npm`, ограничение), сразу отражается в нужном из них в том же изменении.
- **Имя - StreamoScope (две заглавные S), издатель - Froghead Works.** Для людей пишем StreamoScope: README, `docs/DEVELOPMENT.md`, заголовок выпуска (`StreamoScope vX.Y.Z` в `release.yml`), панель в OBS, запись в «Приложениях», заголовок страницы, описание моста; тон текстов - из README и `docs/DEVELOPMENT.md` (сухой юмор «мастерской»). Технический идентификатор - `streamoscope` в нижнем регистре: репозиторий `tjnk24/streamoscope`, файлы выпуска, папки установки и данных, `streamoscope-bridge.lua`, ключи localStorage `streamoscope.*`; раздел параметров профиля - `[StreamoScope]`. До 0.3.0 проект назывался obs-stats-widget: старое имя осталось только в опубликованных заметках `docs/release-notes/0.1.*` и `0.2.0`.
- **Коммит и пуш - только по явной просьбе.**
- **Перед каждым коммитом husky запускает `.husky/pre-commit`**: lint-staged прогоняет eslint (`--max-warnings 0`) и stylelint по изменённым файлам (с `--max-arg-length 4000`: иначе на большом коммите Windows отвечает «Слишком длинная командная строка», а так lint-staged делит список файлов на порции), затем `npm run lint:tsc` проверяет типы всего проекта. Коммит с ошибкой не пройдёт; хук не обходим (`--no-verify` не используем). Хуки включаются сами после `npm install` (скрипт `prepare`).
- **`npm run lint` (tsc, eslint, stylelint, knip) - не после каждой правки**, а перед пушем или по просьбе: knip хук не запускает. **Проверка в браузере - тоже не после каждой правки, а только перед коммитом и пушем** (решение пользователя), на ширине 300 и 670 px; `npm run build:prod` - для неё или когда изменение нужно увидеть в OBS.
- **`.env` не читать.**
- **Проверка в настоящем OBS - тестовый стенд, Claude запускает его сам**: `npm run test:stand` или отдельные команды `npm run stand`, подробности в `docs/internals/testing.md`. Настоящий OBS пользователя не трогаем: перед правкой его настроек - резервная копия, пока идёт игра - ничего в нём не нажимаем.
- **Живую установку через `setup.exe` запускает пользователь из Проводника**, из Claude она попала бы в контейнер MSIX (`.claude/rules/windows/installer.md`).
- **Файлы `.ps1` - только ASCII.**
- **Обещания старым версиям - навсегда**: любая старая версия должна уметь поставить самую новую, поэтому форматы и адреса выпусков из `.claude/rules/releases.md` не меняем.
- **Выпуск и пуш тега - только по явному подтверждению пользователя**, порядок - `.claude/rules/releases.md`. Публикация ждёт его подтверждения в GitHub.
- **После `npm install` и `npm update`, которые меняют `package-lock.json`, проверяем минимальную версию Node** - `.claude/rules/build-and-deps.md`.
