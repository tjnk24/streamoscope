# Правила работы в этом репозитории

OBS Custom Browser Dock: React 19, antd 6, Redux Toolkit, react-router 8, CSS-модули, Rspack (встроенный swc).
Панель открывается с диска (`file:///.../build/index.html`), ходит в obs-websocket на `127.0.0.1` и, при проверке обновлений, в API GitHub за последним выпуском.

## Где что лежит

Правила Claude Code подгружает сам из `.claude/rules/`, когда открыт подходящий файл. Если правка началась без чтения файлов этой области (например, команда `npm install` или выпуск), сначала прочитай нужный файл оттуда - и общий, и свой.

- `.claude/rules/common/` - копия общих правил всех проектов (код, процесс, TypeScript, клиент, Lua, сборка, тесты, Windows, выпуски). Здесь её не правим: правка делается в корне общих правил и копируется его скриптом.
- Остальные файлы `.claude/rules/` и этот файл - только своё: они дополняют общие правила, не повторяют их и с ними не спорят.

Как устроены части программы - `docs/internals/`, читаем перед правкой этой части:

- `bridge.md` - загрузчик моста, автооткат, команды через параметр профиля.
- `updater.md` - `Update-Widget.ps1`: фоновая проверка, порядок установки, статус и ошибки.
- `installer.md` - настройка OBS, раскладка установки, Inno Setup, `minisign.exe`.
- `dock.md` - обновления в панели, плашка моста и переключение коллекций, карточка обновлений, диагностика, ошибки, вход, моки.
- `testing.md` - какими командами что проверять, тестовый стенд.

Форматы настроек OBS - `docs/obs-config.md`, выпуск и обновления для людей - `docs/DEVELOPMENT.md`.

## Безопасность

- **Ключ трансляции никуда не передаём и не показываем.** Из `GetStreamServiceSettings` берутся только `service` и `server`; скрипт-мост отдаёт только схему и хост сервера. Единственное исключение (решение пользователя) - отпечаток выхода в мосте (`outputs/output_fingerprint.lua`): ключ и токен читаются указателем C, без строки Lua, сразу уходят в HMAC-SHA256 `bcrypt.dll` с секретом компьютера, наружу - только 8 символов отпечатка. Так же (решение пользователя) мост считает отпечаток одного ключа без адреса (`keyId`, `mainKeyId` основной трансляции), чтобы панель заметила трансляцию плагина с ключом основной: тот же HMAC, те же указатели C, наружу - те же 8 символов. Так же (решение пользователя) мост считает отпечатки трансляций obs-multi-rtmp до старта (`outputs/multi_rtmp_targets.lua`): ключ и токен из `obs-multi-rtmp.json` профиля читает libobs (`obs_data`), в отпечаток они идут тем же указателем C. Ключ не пишем ни в данные моста, ни в журнал, ни в файлы.
- **Пароль obs-websocket вводит пользователь**, хранится только в localStorage панели и сохраняется всегда после успешного входа (OBS сам держит его открытым текстом в своём конфиге). Сохранённый пароль в поля не подставляем.
- **Исключение - `npm run start:dev`**: dev-сервер отдаёт порт и пароль из конфига obs-websocket (`plugin_config/obs-websocket/config.json` в папке настроек OBS) по `/dev/obs-connection`, читая файл при каждом запросе, слушает только `localhost` и отвечает только своей странице (`isSameOriginRequest`: `Sec-Fetch-Site: same-origin`, остальным - 403, как и эндпоинты журнала). Панель забирает их при старте, если собрана dev-сервером (`process.env.IS_DEV_SERVER`), через `devApi` (`src/api/dev`); в production-сборку этот код и пароль не попадают: вызов стоит прямо в ветке `IS_DEV_SERVER`, а `new DevApi()` и `ky.create` транспорта помечены `/*#__PURE__*/` (проверка - в собранном бандле нет строки `/dev/`).
- **Репозиторий публичный.**

## Процесс

- **Широкое чтение (поиск по проекту, большие файлы, журналы, транскрипты других сессий) - агент `code-reader`, выпуск - скилл `streamoscope-release`, живая проверка установки и удаления - скилл `live-install-check`.** Скилл обновляем в том же изменении, как только видно, что он устарел или нашёлся способ лучше.
- **README.md, страницы для пользователя в `docs/` и docs/DEVELOPMENT.md - только на английском.** README - для пользователя коротко (возможности по строке, установка, ограничения, настройки и приватность, проверка скачанного) со ссылками на подробности: `docs/FEATURES.md` (функции подробно), `docs/HOW-IT-WORKS.md` (мост, отпечатки, обновления, установщик, удаление), `docs/TROUBLESHOOTING.md` (проблемы и советы по иконкам). `docs/DEVELOPMENT.md` - для разработчика (сборка из исходников, команды `npm`, выпуски, проверка обновлений, установщик). Новая площадка - тоже изменение, которое видит пользователь.
- **Имя - StreamoScope (две заглавные S), издатель - Froghead Works.** Для людей пишем StreamoScope: README, `docs/DEVELOPMENT.md`, заголовок выпуска (`StreamoScope vX.Y.Z` в `release.yml`), панель в OBS, запись в «Приложениях», заголовок страницы, описание моста; тон текстов - из README и `docs/DEVELOPMENT.md` (сухой юмор «мастерской»). Технический идентификатор - `streamoscope` в нижнем регистре: репозиторий `tjnk24/streamoscope`, файлы выпуска, папки установки и данных, `streamoscope-bridge.lua`, ключи localStorage `streamoscope.*`; раздел параметров профиля - `[StreamoScope]`. До 0.3.0 проект назывался obs-stats-widget: старое имя осталось только в опубликованных заметках `docs/release-notes/0.1.*` и `0.2.0`.
- **Проверка в браузере - на ширине 300 и 670 px**; `npm run build:prod` - для неё или когда изменение нужно увидеть в OBS.
- **Проверка в настоящем OBS - тестовый стенд, Claude запускает его сам**: `npm run test:stand` или отдельные команды `npm run stand`, подробности в `docs/internals/testing.md`. Настоящий OBS пользователя не трогаем: перед правкой его настроек - резервная копия, пока идёт игра - ничего в нём не нажимаем.
- **Обещания старым версиям** - список форматов и адресов в `.claude/rules/releases.md`, не меняем никогда.
- **Публикация выпуска ждёт подтверждения пользователя в GitHub.**
