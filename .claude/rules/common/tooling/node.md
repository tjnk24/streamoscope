# Node.js и зависимости

- **Минимум - 24**: `.nvmrc` (по нему ставят Node и GitHub Actions) и `engines` в `package.json` (`^24 || >=26`: нечётную 25 исключает vitest). Это наше решение, ниже 24 не опускаем. Меняем - в `.nvmrc`, `engines` и документации проекта.
- **После каждого `npm install`/`npm update`, который меняет `package-lock.json`**, проверяем `engines.node` всех пакетов в нём (и вложенных, и dev): самая высокая нижняя граница и исключённые ветки.
  - Строже нашего `engines` (выше 24 или исключает нашу ветку) - в том же изменении поднимаем минимум в `engines`, `.nvmrc` и документации проекта, в правилах проекта пишем, какой пакет его задаёт, и проверяем на новой минимальной версии из `nvm` (её `node.exe` напрямую, без `nvm use`): production-сборку, упаковку выпуска, если она есть, `npm run lint`, dev-сервер.
  - Пакет перестал поддерживать и 24 - сначала обсуждаем с пользователем: откатить пакет или перейти на новую ветку Node.
  - Что нашли и подняли ли минимум - пишем в ответе.
- **CI ставит пакеты через `npm ci --engine-strict`**: пакет, которому не подходит Node из `.nvmrc`, роняет сборку, а не тихо ставится. Нижние границы внутри 24 (`>=24.5`) так не ловятся, поэтому проверка из пункта выше остаётся.
- **Версии обновляет пользователь руками, примерно раз в год пачкой** (решение пользователя), React - тоже. Dependabot только следит за уязвимостями, всё - в настройках репозитория: Dependabot alerts включены, Dependabot security updates выключены. Файла `.github/dependabot.yml` нет и без решения пользователя не добавляем: его настройки влияют и на PR по уязвимостям.
