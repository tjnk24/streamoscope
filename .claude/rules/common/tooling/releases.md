# Выпуски и GitHub Actions

Разделы про выпуски - для проекта, у которого есть выпуски; состав файлов и адреса - в его правилах.

## Версии

- **Версия - semver, источник - `version` в `package.json`** (в клиенте - `process.env.APP_VERSION`). Номер - по самому крупному изменению:
  - **major** - ломает установку или настройки: ручные действия, несовместимые части, выше требования к окружению;
  - **minor** - новая возможность;
  - **patch** - исправления и косметика: иконки, стили, тексты, переводы.
  - Пока 0.x, ломающее изменение идёт в minor и обязательно описывается в заметках. 1.0.0 - когда несколько выпусков подряд ничего не ломали и установка с обновлением устоялись.
- **Метка сборки - `rspack/init/getBuildLabel`**: пустая только у сборки выпуска в CI по тегу (`GITHUB_REF_TYPE=tag`), у остальных - `git describe --tags --always --dirty --match v*`, вне git - `unknown`. Выпуск - только то, что собрал CI, поэтому метку получает и локальная сборка с коммита выпуска.
  - Номер версии у таких сборок прежний (решение пользователя): по нему сравнивают версии. Метка только для глаз (`process.env.BUILD_LABEL` через `defineGlobals`).

## Сборка и публикация

- **Как выпустить**: заметки `docs/release-notes/<версия>.md`, `npm version <major|minor|patch>` (коммит и тег `v<версия>`), `git push --follow-tags` - только по просьбе.
- **`.github/workflows/release.yml`** по тегу, два задания:
  - `build`: тег совпадает с `package.json`, заметки есть, тесты, сборка, всё из `release/` - в артефакт;
  - `publish`, только для тега и после ручного подтверждения (окружение `release`: подтверждает владелец, только теги `v*`) - последняя проверка человеком. Подписывает файлы и проверяет подписи, пишет `SHA256SUMS.txt`, подтверждает происхождение (`actions/attest`: права `id-token`, `attestations` и `artifact-metadata`; проверка - `gh attestation verify <файл> --repo <владелец>/<репозиторий>`), создаёт GitHub Release. Секретный ключ есть только у `publish`;
  - вручную (`workflow_dispatch`, `gh workflow run release.yml`) - только `build`, без выпуска.
- **`.github/workflows/ci.yml`** на пуш в `main` и pull request.
- **Действия GitHub (`actions/checkout` и другие) - на последних мажорных версиях**, в `uses:` - хеш коммита их выпуска, без комментария с версией. Хеш нового действия или новой версии: `gh api repos/<владелец>/<действие>/commits/<тег> --jq .sha`.

## Обещания старым версиям - навсегда

- Если обновление выполняет уже установленная версия, любая старая должна уметь поставить самую новую. Форматы файлов, имена и адреса, которые она читает, не меняем никогда; их список - в правилах проекта. В файлах, которые читают старые версии, поля только добавляем, существующие не удаляем и не переименовываем.
- Без смены чего-то из списка не обойтись - это ломающий выпуск: старые версии обновятся только вручную, это пишется в заметках.

## Ключ подписи

- Секретный ключ - только в секрете репозитория на GitHub. Его не читаем, не выводим и в репозиторий не кладём.
