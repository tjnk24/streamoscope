# E2e (Playwright, `npm run test:e2e`)

- **Запуск - только `npm run test:e2e`** (сборка и Docker): снимки снимаем и сверяем в одном образе, `npx playwright test` на Windows даст другие шрифты.
- **Раскладка**: `e2e/specs/<область>/{<сценарий>.spec.ts, consts.ts, __snapshots__/<проект>/}` (область - экран; сценарии экрана - файлами в его папке, а не новыми папками, пока их не больше 7; имена снимков в папке не повторяются), страницы - `e2e/pages/<Имя>.ts` (класс: локаторы - `readonly` поля из конструктора, действия - стрелочные поля, без проверок), общее - `e2e/{fixtures,consts,types}.ts`, функции для страницы (`addInitScript`) - `e2e/utils/` по одной на файл. Импорт снаружи папки - алиас `__e2e/*` (`e2e/tsconfig.json`: Node и DOM вместе, лежит в папке, чтобы VS Code нашёл его сам; knip знает его из своих `paths`).
- **Page object из фикстуры**, не синглтон: у каждого теста своя `page`. Новая страница - класс в `pages/` и поле в типе фикстур и `test.extend`.
- **Тест - сценарий пользователя**, шаги - `test.step` с названием по смыслу, тесты друг от друга не зависят, повторов нет (`retries: 0`). Проверки - `expect` в спеке, с подписью у проверок в цикле (`expect(card, 'the live card "X"')`).
- **Локаторы - по роли и подписи** (`getByRole`, `getByText` с `exact`). Классы CSS-модулей и antd не используем. Нет роли и подписи - `data-testid` в разметке, только там, где без него никак.
- **Время - только `page.clock.runFor`**, `waitForTimeout` не пишем. Анимации antd (rc-motion) нужны и кадры по часам страницы, и немного настоящего времени: на медленной машине CI один рывок `runFor` анимацию не доигрывает. Поэтому появление и исчезновение с анимацией (тост, ошибка под полем формы) ждём `utils/advanceClockUntil(page, timeout => expect(...).toBeHidden({timeout}))`: шаги `runFor(ANIMATION_CLOCK_STEP_MS)` в `expect(...).toPass()`, но время страницы за ожидание - всегда одно и то же (`ANIMATION_WAIT_MS`, остаток догоняем после): иначе число срабатываний таймеров страницы зависит от скорости машины и данные на снимках плывут. Проверка на медленной машине - временно `Emulation.setCPUThrottlingRate` (8) в фикстуре `page`.
- **Сеть в тесте** - только подменой: `page.route(<адрес>, route => route.fulfill({json}))` до действия. Действие, которое само ходит в сеть, без подмены уронит тест через сторожа - так и задумано.
- **Снимки, если они есть в проекте**: `toHaveScreenshot` с `fullPage` после `scrollToTop` (липкая шапка иначе ляжет посередине), ARIA - `toMatchAriaSnapshot` с именем. В снимок не попадает то, что меняется с коммитом (версия, метка сборки). Поменял интерфейс нарочно - `npm run test:e2e:update` и новые эталоны в том же коммите, глазами по диффу.
