# Процесс

- **Перед правкой описать, что собираешься менять.**
- **Документация всегда актуальная**: изменение, которое видит пользователь или разработчик (новая функция, настройка, шаг установки, скрипт `npm`, ограничение), сразу отражается в README и нужных файлах `docs/` в том же изменении. Схемы Mermaid - рядом с текстом; высокую схему, которую горизонтально не прочитать, сворачиваем в `<details>`.
- **Коммит и пуш - только по явной просьбе.**
- **Перед каждым коммитом husky запускает `.husky/pre-commit`**: lint-staged прогоняет eslint (`--max-warnings 0`) и stylelint по изменённым файлам (с `--max-arg-length 4000`: иначе на большом коммите Windows отвечает «Слишком длинная командная строка», а так lint-staged делит список файлов на порции), затем `npm run lint:tsc` проверяет типы всего проекта. Коммит с ошибкой не пройдёт; хук не обходим (`--no-verify` не используем). Хуки включаются сами после `npm install` (скрипт `prepare`).
- **`npm run lint` (tsc, eslint, stylelint, knip) - не после каждой правки**, а перед пушем или по просьбе: knip хук не запускает. **Проверка в браузере - тоже не после каждой правки, а только перед коммитом и пушем** (решение пользователя).
- **`.env` и другие файлы с секретами (`.dev.vars`) не читать.**
- **После `npm install` и `npm update`, которые меняют `package-lock.json`, проверяем минимальную версию Node** - `build/node.md`.
- **Выпуск и пуш тега - только по явному подтверждению пользователя**, порядок - `build/releases.md` и правила выпусков проекта.
- **Живую установку через установщик запускает пользователь из Проводника**, а не Claude - `windows/installer.md`.
