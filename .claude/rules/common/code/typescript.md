# TypeScript: типы, утилиты, константы, оформление

Пути вида `types/`, `utils/`, `routes/` в общих правилах - от корня своей части проекта: у клиента это `src` или `src/client`, у сервера и скриптов - их папка. Алиасы `__types`, `__utils` и другие - только у клиента.

## Типы

- **Общие типы и енумы - `types/`**, импорт `__types/<путь>`, внутри `types` - относительно (`./views`, `../i18n/language`).
  - Несколько типов в одном файле - если у них общий смысл и назначение (все ответы одного протокола; настройки и их миграции). Файл называем по смыслу с маленькой буквы, зависимый тип - после того, от которого зависит.
  - Типу не с кем объединиться - лежит один, имя файла = имя типа (`CopyResultEnum.ts`). Объединяем по назначению, а не по соседству: типы про одно и то же, которые служат разному, лежат отдельно.
  - Области - по назначению кода; одинаковые во всех проектах: `app/slices` - внедрённые слайсы страницы и их экшены, `api/request` - слайс запроса и экшены лоадера. Так же устроены типы скриптов и сборки (`rspack/types.ts`).
  - Типы общих функций и классов (`utils`, `services`) в их файлах не объявляем. Типы одной страницы или контейнера - в их `types.ts`.
- **Отсутствие значения - `Nullable<Value>`** (`infrastructure/common`), а не `?:` у обязательного пропа.
- **Параметры типов - по смыслу, не одной буквой**: `Nullable<Value>`, `findResultData<ResultData>`, `preload<WrappedProps>`.
- **Вложенных типов нет**: у поля, параметра, дженерика или приведения не пишем тип-объект на месте (`outputs: {name: string}[]`, `Nullable<{time: number}>`, `({context}: {context: string})`). Каждый объект - именованный тип (`OutputDto`, `BytesSampleDto`), и в `typings/*.d.ts` (`BuildProcessEnv`), и в `rspack/types.ts`.

## Утилиты и константы

- **Утилита - в `utils/`, одна экспортируемая функция на файл**, имя файла = имя функции. Утилита считает данные (`formatPercent`, `drawGraph` рисует на canvas), JSX не возвращает. Функция, которая возвращает разметку (`renderLabel`), - не утилита: нужна одному месту - разметка прямо там (подпись строки - в `items.map` списка), нескольким или держит хуки - компонент.
- **Внутренних хелперов в файле утилиты, класса или компонента нет**: каждая функция уровня модуля - в своём файле. Хелперы одной утилиты или класса - в её папке, `index.ts` реэкспортирует главную функцию, импорт снаружи не меняется (`utils/stats/Tracker/{Tracker.ts, createState.ts, index.ts}`). Хелперы компонента - в его `utils/`.
- **`index.ts` скрипта (`scripts/<имя>/`) только перечисляет шаги**, шаг - своя функция в своём файле, помощники шага - в его папке с реэкспортом в `index.ts`.
- **Утилиты одного назначения - в `utils/<назначение>/`** (общие для всех проектов: `redux`, `hocs`, `api` - основа слоя API, а транспорты и API-классы сервисов - в `api/`). Внутри папки импорт относительный (`./`), снаружи - `__utils/<папка>/<файл>`.
- **Константа уровня модуля - не рядом с функцией** (`const UPDATE_STAGES = [...]`, `RegExp`, код ответа, путь), а в ближайшем существующем `consts.ts` вверх по дереву:
  - `utils/**` и сервисы - `utils/consts.ts`; `rspack/**` - `rspack/consts.ts`; страница - её `consts.ts`; `api/` - `consts.ts` в папке транспорта (базовый адрес и заголовки). Эндпоинты - не в `consts.ts`, а в `routes/api/<api>.ts` (решение пользователя).
  - Новый `consts.ts` не заводим, если выше есть подходящий; свои - только у мест с большим набором данных (`scripts/*`, `tests/consts.ts` и названные в правилах проекта).
  - Исключения: `initialState` слайса (в файле слайса), файлы-данные без функций (словари, роуты в `routes/`, массивы роутов, `theme.ts`), созданные объекты (экземпляры сервисов, `store`, `router`).
- **Тип объявляем только у констант-объектов и массивов объектов** (`DEFAULT_SETTINGS: SettingsDto`, `RULES: RuleDto[]`, `Record<...>`), ключи одинаковых словарей - енумы. Числа, строки, `RegExp`, массивы простых значений - без типа (`RECONNECT_INTERVAL_MS = 3000`), кроме случаев, когда вывод TypeScript не подходит: кортеж для antd (`PROGRESS_SIZE: [number, number]`), `string[]` из `Object.values` енума для сверки со строкой (`UPDATE_STAGES`), `Nullable<...>` с начальным `null`.

## Оформление

- **Поля класса разделяем пустой строкой**, как методы. Присваивания полей в конструкторе (`this.mainCard = ...`) и инструкции в теле методов и функций (`await ...`, `const ...`, `expect(...)`) - тоже каждая через пустую строку, подряд не слепляем (решение пользователя).
- **Импорт от трёх объектов - в столбик** (своё правило eslint проекта `<проект>/import-column`, `--fix` расставит сам).
- **Деструктуризация до 4 полей - в строку, от 5 - столбиком** по полю на строку: пропсы, енумы, внутри функций (`const {Ok, Warn, Bad, Off} = HealthLevelEnum;`). Eslint (`object-curly-newline` для `ObjectPattern`: `minProperties: 5`, `consistent: false`) переносит только скобки, поля расставляем руками. Объект-литерал - тот же порог, даже со всеми сокращёнными полями (`return {version, minVersion, ...}` из шести полей - столбиком); это eslint не ловит.
- **Тернарник в строку - только короткий и одноуровневый** (`type={isClosed ? 'error' : 'info'}`, строка заметно короче лимита).
  - Вложенный - столбиком: условие, `? ветка`, `: ветка` на своих строках, вложенный - с ещё одним отступом. Длинный одноуровневый (вызовы с аргументами, шаблонные строки) - тоже столбиком.
  - Тернарник удлиняет атрибут JSX, вызов функции (`t()`) или шаблонную строку - выносим в константу выше (`message`, `errorKey`, `memoryText`); если константу не завести (аргумент в `case`), аргументы вызова - столбиком.
- **Многострочное выражение аргументом вызова не пишем** (решение пользователя: нечитаемо). Цепочку (`.map(...).filter(...)`), вычисление на несколько строк или собранный объект - сначала в константу с понятным именем, отделённую пустой строкой, а вызов получает её: `const pluginNames = outputs.filter(...).map(...);` (цепочка - столбиком), затем `countBy(pluginNames)`; `const sameNameNote: NoteDto = {...}`, затем `notes.push(sameNameNote)`. Короткий однострочный аргумент (`releaseNotesLoader({per_page: 30})`) - на месте.
  - Так же в скриптах и сборке: опции `new HtmlRspackPlugin({...})` или правило загрузчика - в константу (`htmlPlugin`, `styleRule`), затем `rspackConfig.plugins?.push(htmlPlugin)`; сообщение - в константу, затем `socket.send(JSON.stringify(message))`.
  - Исключение - вызовы, которые сами и есть описание: `createSlice({...})`, `configureStore({...})`, `ky.create`/`extend`, `injectSlices({...})`, `i18n.init({...})`, `defineConfig({...})`, `Object.assign(rspackConfig, {...})` и `flow([...])` в Rspack, фабрика `vi.mock(..., () => ({...}))`, таблица `it.each([...])`: объект прямо в вызове, по строкам.
- **Члены енума не пишем через точку раз за разом**: после импортов енум деструктурируется (`const {Preparing, Downloading} = UpdateStageEnum;`), дальше коротко (`[Preparing]: ...`, `stage === Done`). Для любого файла, где члены одного енума встречаются больше раза: словари в `consts.ts`, компоненты, сервисы, утилиты, `case` в `switch`. Единственное упоминание - через точку. Короткое имя уже занято другим енумом в файле - второй енум через точку.
