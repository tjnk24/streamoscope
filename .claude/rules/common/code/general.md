# Общие правила кода

- **Имена - человекочитаемые, везде**: переменные, параметры, счётчики циклов, константы, функции, на любом языке. Никаких `i`, `n`, `d`, `x`, `K`, `H0`, `t1`, `ror`, `cb`, `el` - имя говорит, что лежит внутри (`wordIndex`, `candidate`, `divisor`, `roundConstants`, `rotateRight`). Даже если так названо в стандарте или алгоритме - даём смысловое имя. Поля чужих протоколов при деструктуризации переименовываем: `{op: opCode, d: data}`. Неиспользуемый параметр - `_` плюс имя (`_output`, `_index`).
- **Сначала прецедент, потом код.** Новый роут, селектор, слайс, сервис пишутся так же, как соседние.
- **Выносим только то, что повторяется.** Разовый текст - в разметке, а не в `consts.ts`; хелпер с одним вызовом - в месте вызова.
- **Больше 7 файлов одного вида в папке - раскладываем по подпапкам по смыслу** (типы, утилиты, компоненты, модули, функции скриптов): по области, как `types/<область>` или `utils/<назначение>/`, а не по алфавиту или виду файла.
  - Подпапки - не глубже трёх уровней от исходной папки, в каждой - тоже не больше 7 файлов, иначе делим её дальше. Подпапка из одного файла не нужна: такой файл остаётся уровнем выше. Добавляя файл в папку, где уже 7, сначала раскладываем папку.
  - Исключение - папки данных страницы `api/`, `services/`, `loaders/`, `selectors/` и `reducers/` и эндпоинты API в `routes/api/`: они есть всегда, даже с одним файлом, чтобы искать их в одном месте. Так же всегда есть `hooks/`, `utils/` и `tests/` компонента, контейнера или утилиты (их требуют `react/structure.md` и `tests/vitest.md`), папки по виду кода `utils/hocs` и `utils/dev`, модуль типов `typings/infrastructure` (по нему идёт импорт `infrastructure/common`) и папки не с кодом: `config`, `.vscode`, папки образцов и данных, названные в правилах проекта.
  - Не считаются корень репозитория (конфиги инструментов должны лежать там) и служебные папки инструментов (`.husky/_`, `node_modules`, папки сборки).
- **Комментариев в коде нет совсем**, на любом языке, в стилях и конфигах тоже. Остаются только директивы инструментов (`/* eslint-disable ... */`, `/// <reference ... />`, `/*#__PURE__*/` перед созданием объекта, который production-сборка должна выбросить, когда он не используется). Пустой `catch` без комментария - `catch { return; }`.
- **Личных путей, личных данных и секретов в репозитории нет**, даже в приватном.
