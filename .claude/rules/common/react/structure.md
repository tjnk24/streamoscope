# Клиент: раскладка страниц, компонентов и хуков

- **Страница - папка `pages/<Страница>/`**: `index.ts` отдаёт роуты из `routing.tsx` (массив `RouteObject`), разметка - `containers/page`, свои компоненты - её `components/` и `containers/`. Данные - `reducers/`, `selectors/` (файл на слайс), `actions.ts`, `api/`, `services/`, `loaders/`; эти папки заводим и с одним файлом (решение пользователя).
- **Компонент или контейнер - по тому, откуда данные.**
  - Компонент (`components/`) - только разметка по пропсам, без стора, сервисов и экшенов.
  - Контейнер (`containers/`) берёт данные сам (селектором, своим хуком с селектором или через сервис) и сам вызывает сервисы и экшены. Поэтому карточка в `map`, которая сама достаёт данные, - контейнер.
  - `containers/page` - сама страница, может только расставлять контейнеры без своих данных.
  - Общие для нескольких страниц - `components/` в корне клиента, стор трогать могут; отдельной `containers/` в корне нет.
- **Контейнер не получает данные пропсами**: селектор, вычисление и обработчик (сервис или экшен) - внутри, даже если родитель уже выбрал те же данные для своего решения.
  - Пропсом приходит только то, что знает один родитель, - элемент списка в `map`.
  - Данные могут быть `null`, а родитель показывает контейнер, только когда они есть, - контейнер всё равно берёт их сам, его хук возвращает `null` без данных.
- **Роуты собирает `pages/Core/containers/page/appRoutes.tsx`.** Импорт из `__pages/*` - только там и в `index.tsx` клиента; общее для нескольких страниц - в `{api,components,utils,selectors,services,reducers,loaders}` корня клиента.
- **Утилиты, хуки и константы - там, где используются.** Нужное одной странице - её `utils/`, `hooks/`, `consts.ts`: уровня страницы, если нужно нескольким контейнерам, уровня контейнера - если одному. В общих `utils` и `utils/consts.ts` - нужное нескольким страницам или не страницам: сервисам, стору, `index.tsx`. Утилиты сервиса в `services` не переносим.
- **Цепочка вычислений для разметки - хук `use<Что>View`** в `hooks/` контейнера, если компонент считает по стору несколько зависящих друг от друга значений (статус, этап, проценты, ключи текстов).
  - Хук сам берёт стор, вызывает `Date.now()`, считает и возвращает `<Что>ViewDto` (тип в `types.ts` контейнера) только с нужным разметке; утилиты под ним не заводим.
  - Компонент деструктурирует результат: `const {statusText, errorText, isUpdateShown} = useUpdateSettingsView();`.
  - Если есть переводы, хук может переводить сам (`t` из `useTranslation`); если отдаёт JSX - файл `.tsx`.
  - Одна простая константа остаётся в компоненте.
  - Тест такого хука - `tests/vitest.md`.
- **В папке компонента или контейнера - один `.tsx`.**
- **Порядок в начале компонента и хука**: селекторы (`useSelector`) -> стейты (`useState`) -> хуки (`Form.useForm`, `useTranslation`, `theme.useToken`, `useMatch`, свои хуки, `useRef`) -> константы (производные данные, обработчики) -> эффекты и `return`.
  - Группы разделены пустой строкой; селекторы подряд, стейты подряд, а каждый хук и каждая константа (и после раннего `return`, и внутри `if`) отделены пустой строкой.
  - `useTranslation` не стоит первым, если есть селекторы или стейты.
- **Отдельный компонент или контейнер - только когда оправдан**: используется в нескольких местах, рендерится в `map` и держит хуки, несёт свою логику (эффекты, canvas, расчёт) или нужен в `memo`, чтобы React пропускал неизменную часть того, что часто перерисовывается. Обёртка, которую рендерит одно место, - разметка в родителе: контейнер, который и есть вся страница, сливается с ней (форма прямо в `containers/page`), обёртка над одним компонентом antd без логики (`Tag`, `Alert` с готовыми пропсами) - на месте.
- **Громоздкий контейнер с несколькими состояниями делим**: родитель только выбирает и возвращает дочерний контейнер или короткий `Alert`, каждое состояние со своей логикой - отдельный контейнер рядом.
